# 自动化 i18n 测试方案

## 1. 目标

基于 Playwright 实现全自动化的国际化（i18n）缺失检测，覆盖所有页面（设置、聊天、侧边栏、弹窗等），输出详细的测试报告。

## 2. 核心策略

利用现有的 `playwright` 测试框架，结合应用内的路由机制，实现自动爬虫和内容校验。

### 2.1 自动化遍历 (Crawler)

* **原理**: 利用 `shared/routes.ts` 中定义的路由，通过 `navigate()` 函数编程控制页面跳转，无需人工点击。

* **覆盖范围**:

  * **设置页面**: 遍历 `settings-registry.ts` 中定义的所有子页面 (App, AI, Appearance, Input, Workspace 等)。

  * **主功能区**: 聊天列表 (All Sessions), 侧边栏 (Sidebar), 插件管理 (Skills), 数据源 (Sources)。

  * **弹窗**: 尝试触发“新建聊天”、“编辑会话”等常用弹窗。

### 2.2 智能检测 (Verification)

* **硬编码文本检测**:

  * **环境**: 强制应用以 `zh-CN` (简体中文) 启动。

  * **规则**: 扫描页面所有可见文本，若发现包含连续的英文字符（排除 AI, API, Claude, GPT 等专有名词），则标记为“疑似硬编码”。

  * **过滤**: 自动忽略数字、符号、代码块、文件路径等非翻译内容。

* **缺失 Key 检测**:

  * **规则**: 扫描页面文本，若发现形如 `pages.home.title` 或 `common.submit` 的字符串（包含点号且无空格），则标记为“缺失翻译 Key”。

### 2.3 报告输出

* **格式**: 生成 `test-results/i18n-report.json` 和控制台摘要。

* **内容**: 包含出错页面、元素选择器 (Selector)、问题文本、严重程度。

* **截图**: 对发现问题的页面自动截图（可选）。

## 3. 实施步骤

1. **环境准备**: 确保测试环境能加载 `zh-CN` 配置。
2. **路由集成**: 在 `i18n-e2e.spec.ts` 中引入项目路由定义。
3. **爬虫实现**: 编写 `navigateAndCheck` 辅助函数，实现“跳转 -> 等待 -> 检查”的循环。
4. **算法优化**: 优化 `isLikelyHardcodedText` 函数，增加白名单机制，减少误报。
5. **执行验证**: 运行测试并生成报告。
