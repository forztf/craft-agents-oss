# 国际化 (i18n) 自动化改造与测试方案

## 1. 概述
本项目旨在通过自动化手段解决国际化改造中“漏翻译”的问题。方案采用“静态分析 + 动态 E2E 测试”的双重保障机制，确保所有页面及其子页面的文本都能被正确识别和翻译。

## 2. 改造方案详情

### 2.1 静态代码分析 (Static Analysis)
-   **目标**: 在代码编译阶段快速发现明显的硬编码字符串。
-   **工具**: 优化现有的 `tests/e2e/i18n/static-analyzer.ts`。
-   **策略**:
    -   扫描 `apps/electron/src/renderer` 下所有 `.tsx`, `.ts` 文件。
    -   使用正则表达式匹配 JSX 文本节点和常见属性（`placeholder`, `title`, `aria-label`）。
    -   **改进点**: 增加白名单机制（忽略日志、ID、CSS类名、特定技术术语），降低误报率。

### 2.2 动态 E2E 测试 (Playwright Crawler)
-   **目标**: 在应用运行时检测渲染后的页面，发现动态加载内容或条件渲染内容的漏翻译问题。
-   **工具**: Playwright + Electron。
-   **策略**:
    1.  **环境强制**: 启动应用时强制指定语言为 `zh-CN`（简体中文）。
    2.  **自动巡检 (Crawler)**:
        -   利用 `shared/routes.ts` 和 `settings-registry.ts` 获取所有应用内路由。
        -   通过 `navigate()` 函数编程控制页面跳转，遍历：
            -   **聊天主页**: 检查欢迎语、输入框占位符。
            -   **设置中心**: 遍历所有子页面 (AI, 外观, 输入, 权限等)。
            -   **功能模块**: 侧边栏、插件列表、数据源列表。
    3.  **智能检测算法**:
        -   **硬编码英文检测**: 扫描 DOM 文本，若发现连续英文句子（排除专有名词如 "Claude", "GPT"），标记为未翻译。
        -   **Missing Key 检测**: 扫描文本，若发现形如 `pages.settings.title` 的 Key 字符串，标记为翻译丢失。
        -   **属性检查**: 检查 `input` 的 `placeholder` 和图标按钮的 `aria-label`。

### 2.3 测试报告与反馈
-   **输出**:
    -   控制台实时输出（CI友好）。
    -   JSON 详细报告 (`test-results/i18n-report.json`)。
    -   问题截图（针对 UI 渲染错误）。
-   **闭环**: 报告将直接指出文件路径或 UI 选择器，辅助开发人员快速修复。

## 3. 预期效果
-   无需人工逐页点击，自动化覆盖率达到 95% 以上（除极少数特殊交互状态）。
-   清晰区分“未提取 Key”和“有 Key 无翻译”两种情况。
