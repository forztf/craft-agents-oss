## 1. 产品定位与核心价值

### 1.1 产品定位

**Craft Agents** 是一个桌面 AI 客户端，专为与 Claude Agent 和 OpenAI Codex 进行高效协作而设计。它遵循"Agent-Native"（原生代理）软件理念，提供图形化界面替代传统 CLI 方式，使用户能够通过自然语言描述意图，由 AI 自主规划和执行任务。

### 1.2 核心价值主张

| 价值维度 | 描述 |
|---------|------|
| **直观多任务** | 多会话管理、状态工作流、标记功能，支持并行处理多个任务 |
| **无缝连接** | 自动发现和配置公共 API、MCP 服务器，无需手动配置文件或向导 |
| **会话共享** | 支持会话持久化和分享，方便团队协作 |
| **文档中心化** | 偏向文档而非代码的工作流，适合非开发人员使用 |
| **高度可定制** | 通过自然语言提示即可自定义功能，无需代码编辑 |

### 1.3 目标用户

- craft.do 内部团队
- 需要与 AI 代理协作的开发者和产品团队
- 希望使用图形界面替代 CLI 的技术用户
- 需要集成多个 API/服务的自动化场景用户

### 2.2 技术栈

| 层级 | 技术 | 说明 |
|-----|------|------|
| 运行时 | Bun | 高性能 JavaScript 运行时 |
| AI 引擎 | @anthropic-ai/claude-agent-sdk | Anthropic 官方 Agent SDK |
| AI 备选 | Craft Agents Codex fork | 支持 OpenAI 连接的分支 |
| 桌面框架 | Electron | 跨平台桌面应用框架 |
| UI 框架 | React + TypeScript | 渲染进程框架 |
| UI 组件库 | shadcn/ui + Tailwind CSS v4 | 样式系统 |
| 构建工具 | esbuild (main) + Vite (renderer) | 编译打包 |
| 凭证存储 | AES-256-GCM | 加密文件存储 |
| 状态管理 | Jotai | 原子化状态管理 |

## 3. 模块边界初步划分

基于代码库扫描，将项目划分为以下功能模块：

### 3.1 核心业务模块

| 模块名称 | 边界范围 | 包含组件/文件数 |
|---------|---------|---------------|
| **会话管理** | Session CRUD、状态工作流、持久化、搜索、标记 | 9个组件 |
| **工作区管理** | Workspace CRUD、切换、配置 | 3个组件 |
| **Sources 集成** | MCP 服务器连接、REST API 集成、本地文件系统 | 10+个组件 |
| **Skills 管理** | 自定义技能 CRUD、触发机制 | 5+个组件 |
| **AI 聊天** | 聊天界面、消息渲染、工具调用可视化、Diff 视图 | 8+个组件 |
| **权限控制** | Permission Modes、安全规则配置 | 3层权限系统 |
| **API 配置** | API Key 输入、OAuth 连接、多提供商支持 | 3个组件 |

### 3.2 UI 基础模块

| 模块名称 | 边界范围 | 说明 |
|---------|---------|------|
| **App Shell** | 主应用框架、侧边栏、面板、工作区切换器 | 23个组件 |
| **Onboarding** | 引导流程、API 设置步骤、完成界面 | 4个步骤组件 |
| **Settings** | 设置页面、AI 配置、外观、快捷键等 | 12个设置页面 |
| **快捷键系统** | 键盘事件处理、快捷键定义、标签生成 | 5个文件 |

### 3.3 跨领域关注点

| 关注点 | 实现方式 |
|-------|---------|
| **国际化 (i18n)** | 自定义 I18nContext + useTranslation hook，使用英文原文作为 key |
| **主题系统** | 级联主题配置（应用级 → 工作区级），6色系统 |
| **凭证安全** | AES-256-GCM 加密存储于 `~/.craft-agent/credentials.enc` |
| **配置管理** | 多工作区配置，文件监听实时更新 |
| **事件处理** | Agent 事件处理器，结构化输入/请求处理 |

## 5. 用户旅程

### 5.1 新用户首次使用

```
1. 启动应用 → 展示 Splash Screen
2. 首次运行 → 进入 Onboarding Wizard
   - API Setup 步骤（Anthropic/Codex 选择）
   - Credentials 步骤（API Key 输入）
   - Completion 步骤（欢迎信息）
3. 创建第一个 Workspace
4. 连接 Sources（可选）
5. 创建第一个 Session
6. 开始与 Agent 交互
```

### 5.2 典型使用场景

#### 场景 1: 配置新 Source
```
用户: "Add Slack as a source."
系统: 自动发现 Slack MCP 服务器 → 读取文档 → 设置凭证 → 配置完成
```

#### 场景 2: 使用自定义 Skill
```
用户: "@my-analyze-skill analyze the recent data"
系统: 执行自定义技能 → 调用相关工具 → 返回结果
```

#### 场景 3: 权限控制
```
用户: 正在执行 bash 写操作
系统 (Ask 模式): 提示用户批准
用户: 批准或拒绝
系统: 根据决定继续或中止操作
```

## 6. 技术亮点

### 6.1 Agent-Native 设计理念

- **意图驱动**: 用户描述想要什么，AI 决定如何实现
- **自然语言编程**: 通过提示而非代码进行定制
- **自适应工具**: 根据任务动态选择和使用工具

### 6.2 安全架构

- **加密存储**: 所有敏感凭证 AES-256-GCM 加密
- **子进程隔离**: 本地 MCP 服务器独立运行，环境变量过滤
- **分级权限**: 三级权限系统 + 自定义规则
- **凭证缓存**: Bridge MCP Server 被动刷新机制

### 6.3 开发体验

- **Monorepo 架构**: apps 和 packages 分离，清晰的依赖关系
- **TypeScript 全覆盖**: 类型安全，减少运行时错误
- **热重载开发**: `bun run electron:dev` 快速迭代
- **子路径导出**: 清晰的模块导入接口

### 6.4 性能优化

- **大型响应摘要**: 智能压缩超长响应
- **异步持久化**: 会话存储使用防抖队列（500ms）
- **文件监听**: 配置实时更新，无需重启

## 9. 风险与约束

### 9.1 已知约束

- **开源协议**: Apache 2.0 许可，需遵守 Anthropic 商业条款
- **依赖锁定**: 必须使用现有技术栈，不引入新依赖
- **代码编辑器策略**: 团队内部使用 Craft Agents 自身开发，不使用传统代码编辑器

### 9.2 潜在风险

- **大型文件**: 部分组件文件过大（如 AppShell.tsx ~29000 tokens），影响编辑效率
- **并发编辑**: 多进程同时修改大文件可能导致冲突
- **API 变更**: 依赖外部 API（Claude/Antropic），需考虑向后兼容性
